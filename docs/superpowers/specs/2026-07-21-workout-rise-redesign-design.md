# workout.html RISE식 재설계 — 설계 문서

- 작성일: 2026-07-21
- 대상 파일: `workout.html` (단일 정적 HTML, 빌드/번들 없음)
- 참고: RISE 운동 앱 (com.cheezebucket.rise) — 루틴 목록/생성 중심 모바일 앱

## 1. 배경과 목표

현재 `workout.html`은 데스크톱 대시보드형이다. 요일별로 **하드코딩된** 추천 루틴 체크리스트 +
세션 요약 기록 폼(이름·시간·메모) + 주간 통계로 구성된다. 한계:

- 사용자가 루틴을 만들 수 없다 (`ROUTINES`가 요일별 하드코딩).
- 세션 기록에 운동별 **세트/무게/횟수**가 없다 — 헬스 앱의 알맹이가 없음.
- 진행도(볼륨·PR) 추적이 없다.
- 실시간 "운동 실행" 경험이 없다 (끝난 뒤 요약만 기록).

목표: RISE식 **루틴 목록 → 루틴 생성 → 실시간 운동 실행 → 기록/통계** 흐름을 갖춘,
모바일=앱 / 데스크톱=대시보드로 동작하는 반응형 단일 페이지 앱으로 재설계한다.
기존의 세션 기록·주간 통계 개념은 새 모델에 흡수한다.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 방향 | RISE식 루틴 목록/생성 + 기존 기록·통계 결합 |
| 레이아웃 | 반응형: 모바일=단일 컬럼+하단 탭바, 데스크톱=넓은 대시보드 그리드 |
| 기록 깊이 | 루틴=운동 목록, 운동=세트별 무게·횟수, 실시간 운동 모드에서 세트 체크 |
| 화면 구조 | 3탭(루틴 · 기록 · 통계) + 운동 모드 풀스크린 오버레이 |
| 다크모드 | 라이트 전용 (RISE 톤에 충실, 범위 절감) |
| 통계 차트 | 포함 — 순수 canvas 주간 볼륨 막대차트 (외부 라이브러리 없음) |

## 3. 데이터 모델

`localStorage` 키: **`fg-workout-v2`** (신규).

```js
state = {
  routines: [
    {
      id: string,           // 고유 id
      emoji: "🌱",          // 루틴 아이덴티티
      name: "이두 루틴",
      note: "",             // 선택 설명
      exercises: [
        {
          id: string,
          name: "바벨 컬",
          sets: [            // 목표 세트
            { weight: 20, reps: 12 },
            { weight: 20, reps: 10 }
          ]
        }
      ]
    }
  ],
  logs: [
    {
      id: string,
      date: ISOString,      // 완료 시각
      routineId: string|null, // null = 자유 운동
      emoji: string,
      name: string,         // 루틴명 또는 "자유 운동"
      exercises: [
        { name, sets: [ { weight, reps, done: true } ] }
      ],
      durationMin: number,
      note: string
    }
  ]
}
```

**파생 계산 (logs에서):**
- 세션 볼륨 = Σ(set.weight × set.reps), done 세트만 집계.
- 주간 볼륨/시간/횟수 = 이번 주(일~토) logs 필터 후 합.
- 스트릭 = 오늘 기준 연속으로 log가 있는 일수.
- 최다 루틴 = logs의 name 빈도 1위.
- PR = 운동명별 최고 weight (선택: 볼륨 기준).

### 마이그레이션

로드 시 `fg-workout-v2`가 없고 기존 `fg-workout-dashboard`가 있으면 1회성 변환:
- 기존 `sessions[]`(각 `{name, category, minutes, intensity, note, date}`)을 `logs[]`로 이관.
  - `exercises: []`(세트 데이터 없음), `durationMin: minutes`, `routineId: null`, `emoji: "🏋️"`.
- 기존 `checks`(요일 체크)는 새 모델에 대응 개념이 없으므로 이관하지 않음.
- 원본 `fg-workout-dashboard` 키는 삭제하지 않고 백업으로 남긴다.
- 변환 결과를 `fg-workout-v2`에 저장하여 재변환을 방지한다.

## 4. 화면 구조

### 공통 셸
- 상단: 라이트 앱 헤더 — 좌측 `← 포트폴리오`(홈 복귀), 중앙/좌 로고 "RISE"풍 워드마크.
  - 기존 공용 다크 `.topnav`는 제거하고 라이트 앱 헤더로 대체. 허브 복귀 링크로 이동성 유지.
- 하단(모바일): 고정 탭바 3개 — 루틴 · 기록 · 통계. 데스크톱에서는 상단/사이드 탭으로 표현.
- 탭 전환은 단일 상태(`activeTab`) + 렌더 함수로 처리 (URL 해시 선택적 반영 가능).

### 4.1 루틴 탭
- 루틴 카드 목록: `[이모지] [이름] "운동 N개 · 예상 N분" ......... [⋮]`
  - `⋮` 메뉴: 편집 / 복제 / 삭제(확인 후).
  - 카드 탭 → 루틴 상세 뷰(운동·세트 미리보기) + `운동 시작` 버튼.
- 리스트 하단: `+ 루틴 만들기`(점선/흐린 스타일), `▶ 자유 운동 시작`(민트 CTA).
- 빈 상태: "첫 루틴을 만들어보세요" 온보딩 + 예시 프리셋 제안(선택적으로 기본 루틴 시드).

### 4.2 루틴 편집기 (모달 또는 풀스크린)
- 이모지 선택(간단한 프리셋 팔레트), 루틴명, 설명.
- 운동 추가/삭제(드래그 정렬은 범위 밖 — YAGNI).
- 운동별 세트 추가/삭제, 세트마다 무게(kg)·횟수 입력.
- 저장 시 `routines[]`에 반영, 편집이면 해당 id 갱신.
- 모든 사용자 입력 텍스트는 렌더 시 `esc()` 처리.

### 4.3 운동 모드 (풀스크린 오버레이, 탭 아님)
- 진입: 루틴 상세의 `운동 시작` 또는 `자유 운동 시작`.
- 상단: 경과 시간 타이머(시작 시각 기준, `requestAnimationFrame` 또는 1s interval).
- 운동/세트 리스트: 세트 하나씩 `완료` 체크(토글), 무게·횟수 인라인 수정 가능.
- 자유 운동: 빈 상태에서 운동/세트를 즉석 추가.
- `운동 종료` → done 세트만 모아 `logs[]`에 저장, 오버레이 닫고 기록 탭 갱신.
- 종료 없이 이탈 방지: 진행 중 닫기 시 확인(브라우저 `confirm` 대신 인라인 확인 UI 권장).

### 4.4 기록 탭
- 완료 로그 역순 리스트: `[이모지] [루틴명]  [날짜]` / `볼륨 · 시간 · 세트수` / 메모.
- 상단에 주간 스트립(●=운동함 / ○=없음) 유지 — 기존 감각 계승.
- 빈 상태 안내.

### 4.5 통계 탭
- 요약 타일: 이번 주 볼륨 / 이번 주 시간 / 이번 주 횟수 / 스트릭 / 누적 로그.
- 주간 볼륨 막대차트: 최근 N주(예: 8주) 볼륨을 순수 canvas 막대로. 라이트 톤, 접근 가능한 대비.
- 최다 루틴, PR 하이라이트(운동별 최고 무게 상위 몇 개).

## 5. 레이아웃/스타일

- 톤: 풀-라이트. 배경 옅은 회색(`#F4F6F8` 계열), 카드 흰색+radius 14px+옅은 그림자.
- 액센트: 민트/에메랄드(`#10b981` 계열). CTA·강조·완료 상태에 사용.
- 이모지를 루틴/운동 아이콘으로 사용(커스텀 아이콘 대신 친근함).
- 폰트: 기존 Inter 유지(굵은 산세리프).
- 모바일: `max-width ~460px` 중앙 컬럼, 하단 고정 탭바(`position:fixed; bottom`).
- 데스크톱: 콘텐츠를 넓은 그리드로 확장(예: 루틴 목록 + 우측 통계/기록 패널). 탭바는 상단/사이드.
- 애니메이션: 기존 pageIn 및 탭/오버레이 전환에 가벼운 트랜지션.

## 6. 코드 품질/정리 항목

- `alert()` 검증 제거 → 인라인 에러 메시지로 교체.
- 사용자 입력(루틴명·운동명·메모)은 렌더 시 `esc()` 필수.
- 렌더는 상태→DOM 단방향: `render()`가 `activeTab`에 따라 해당 탭 렌더 함수 호출.
- 함수 분리: `loadState/persist/migrate`, `renderRoutines/renderHistory/renderStats`,
  `openEditor/saveRoutine`, `startWorkout/finishWorkout`, `drawVolumeChart`.
- 4-space 들여쓰기, camelCase JS, kebab-case CSS, 한국어/영어 UI 패턴 유지.

## 9. 성공 기준

- 루틴을 만들고(이모지·운동·세트) 목록에서 보이며, 새로고침 후에도 유지된다.
- 루틴/자유 운동을 시작해 세트를 체크하고 종료하면 기록 탭에 로그가 남는다.
- 통계 탭이 이번 주 볼륨·스트릭·주간 볼륨 차트를 정확히 표시한다.
- 모바일 폭에서 하단 탭바로 3탭 전환이 매끄럽고, 데스크톱에서 넓은 레이아웃으로 확장된다.
- 기존 `fg-workout-dashboard` 데이터가 있던 사용자는 과거 세션이 기록 탭에 이관되어 보인다.
- `alert()` 없음, 사용자 입력 XSS 안전(`esc()` 적용).
